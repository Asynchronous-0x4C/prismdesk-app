# HDR

PC の HDR の映像を、HDR のままタブレットに届けられます。SDR に落としてから HDR の札を
付け直すのではなく、BT.2020 と PQ カーブのまま、端から端まで通します。

自分でオンにするものではありません。PC と端末がそれぞれ何をできるかを確かめて、
見た目が本当に変わるときに HDR を選びます。HDR にならないときは、何が足りないかを
PrismDesk が言います。

## そろっている必要があるもの

| | |
|---|---|
| **端末が HEVC Main10 をデコードできる** | HDR10 は H.265 で送ります。H.264 の HDR はありません。 |
| **端末のディスプレイが HDR10 か HLG を申告している** | Android がパネルについて申告する内容で、パネルの実力そのものではありません。 |
| **パネルが SDR より明るくできる** | その倍率を Android が教えてくれます。上限が 1.0 なら HDR10 にしても SDR と同じに見えるので、既定は SDR のままです。 |
| **PC が 10 ビットでエンコードできる** | ホストを起動したときに 1 回だけ確かめます。できない GPU では、つなぐたびに失敗させるのではなく、最初から HDR を切っておきます。 |
| **PC で PrismDesk Pro が動いている** | HDR は Pro の機能です。アプリの「色空間」の「HDR10（Pro）」は、PC が無料版だと押せず、ホストは SDR で送ります。 |

最初の 2 つのどちらかが欠けていると、アプリはどれが欠けているかを出します。

- 「この端末は HEVC Main10 のデコードと HDR 表示のどちらにも対応していません。」
- 「ディスプレイは HDR に対応していますが、HEVC Main10 をデコードできません。」
- 「HEVC Main10 はデコードできますが、ディスプレイが HDR10/HLG を報告していません。」

アプリの［設定］の「色空間」には、つなぐ前に、手元の端末で自動の答えがどうなるかが
出ます(「この端末では HDR10 になります。」か「この端末では SDR になります。」)。
**SDR と HDR10 は自分で選ぶこともできます。**HDR を活かせないパネルで HDR10 を選ぶことも
できて、そのときはどうなるかをアプリが先に言います。

## 「HDR がオン」と「HDR が届いた」は別のこと

Windows が HDR になっていても、実際に取り込まれているのは HDR の札が付いた SDR の絵、という
ことがあります。この失敗は、PC のどのスイッチを見ても成功しているように見えます。だから
ホストは設定を信じずに、実際に測ります。

PC では、ホストのウィンドウ左下の「詳細表示」を入れると、［接続］タブに「HDRの実測値」の
欄が出ます(測り直すボタンもあります)。「本当に HDR が届いているのか」への答えはここで、
設定からではなく絵そのものから取った値です。

## HDR を活かせないパネル

上の条件を全部満たしていても、何も変わらない端末があります。Android はパネルが SDR より
どれだけ明るくできるかを教えてくれますが、パネルによってはその倍率が 1.0 です。HDR10 で
送られてデコードもされますが、見た目は SDR と同じです。

自動の答えが「デコードできるか、表示できるか」だけでなくこの倍率を見るのはそのためです。
Android 16 より前の端末は上限そのものを教えてくれないので、こちらも SDR のままにします。
読めない上限は、満たしているとは言えないからです。アプリは選ぶところでこう言います。

> 「この端末のパネルは HDR の輝度域に入りません（HDR/SDR 比の上限が 1.0）。HDR10 で送れますが、明るさは SDR と同じになります。」

## 測ったもの

**Google Pixel 9** で:

| | |
|---|---|
| `hdrSdrRatio` | **7.999703**(SDR なら 1.0) |
| 色空間(要求したものと、出たもの) | **BT.2020 / PQ / limited** —— どちらの端でも黙って格下げされていない |
| SDR の白の輝度コード値 | 期待値 588、実測 **588** |

同じ PC・同じ画面・2944x1840 / 60 Hz・低遅延のプロファイルで:

| 接続 | フレームレート | ビットレート |
|---|---|---|
| H.265・HDR10 | 38 fps | **2,800 kbps** |
| H.265・SDR | 38 fps | 6,800 kbps |
| H.264・SDR | 38 fps | 7,100 kbps |

**このときは、HDR10 のほうが SDR より通信量が少なくすみました。**どの行も 1 回だけ、
1 台の PC、画面に出していた 1 枚の絵での値です。「この絵では HDR にしても通信量は増えなかった」と
読んでください。計画に使える数字ではありません。

接続が始まるまでは、**HDR で 0.97 秒、HDR なしで 0.82 秒**でした(同じ測り方で、各 1 回)。

**測っていないもの:** HDR と SDR の GPU の負荷の差と、動く映像での通信量。どちらも、
どこにも書いていません。
